Asana Task — LearnPress Tutor Booking v1.2 dual-confirm

Template task triển khai / QA theo logic hiện tại (dual confirmation + delayed revenue).

Business Goal

Mở rộng LearnPress sang booking live tutoring native: instructor có profile, session types, availability, booking, dual-sided session confirmation, trusted payout, review, dispute, email, revenue share, và dashboard trong cùng hệ sinh thái.

Core Requirements

  • Canonical tutor profile per user.
  • Session type: price, duration, buffer, status, meeting link override.
  • Availability weekly / custom / holiday.
  • Timezone chooser + current datetime preview; admin default = WordPress timezone.
  • Past/started slots disabled.
  • Hold → LP Checkout → booking confirmed (paid).
  • Paid ≠ instructor earned. Revenue share snapshot on hold; commission credit only after dual confirm or admin release.
  • Instructor Confirm Taught; student Confirm Learned (optional stars + message).
  • Both confirmed → completed + revenue_released + lp_commission_add_commission once.
  • Student Complaint (reason) → disputed → admin resolve: release_revenue / complete / cancel / refund / no_show.
  • Shortcode sessions: tutor name, rating, bio when profile_id set.
  • Tutor Booking confirmation emails in LearnPress Emails tab.
  • Setting lp_tb_meeting_link_visible_minutes: Join/Open Meeting unlocks N minutes before start (0 = show immediately after paid). Locked state shows unlock message. Default emails do not include the meeting URL (unlock notice only). Variable {{meeting_link}} still resolves if an admin customizes the LP email body.

Out of Scope

  • Group session flow.
  • Auto-generated Zoom / Meet link.
  • Auto-timeout dual-confirm (v1.1+).
  • Webhook system riêng.
  • Multisite support.
  • Comparison pages trong docs nội bộ.

Acceptance Focus

  • Student chỉ book slot hợp lệ; payment → confirmed; commission balance không tăng sớm.
  • Confirm Taught + Confirm Learned → completed + single commission credit.
  • UI: Pending earn vs Earned theo revenue_released.
  • Complaint → admin filters Disputed; resolve actions hoạt động.
  • Meeting link fallback: booking → session type → profile.
  • Admin đổi revenue share chỉ ảnh hưởng booking mới (snapshot).
  • Student Join Session khi confirmed; shortcode hiện stars khi có reviews.

Implementation Notes

  • DB migration 1.0.4: dual-confirm columns + backfill legacy completed as revenue_released.
  • Services: Booking_Service (confirm_taught/learned, open_complaint, admin_resolve, release_revenue), Review_Service.
  • REST: /confirm-taught, /confirm-learned, /complaint, /resolve.
  • Architecture living doc: learnpress-tutor-booking/AI-AGENT-FEATURES-ARCHITECTURE.md.
